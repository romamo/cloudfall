# Proving run: M9 graduated autonomy on a real Hetzner host

| | |
| --- | --- |
| **Date** | 2026-09-10 |
| **Scope** | M9 exit criteria: an induced failure remediated autonomously within declared policy, alert to healthy service with zero human involvement, receipts showing detection, decision, action, and verified outcome |
| **Host** | Hetzner Cloud cx23 (fsn1), stock Debian 13 image, deleted after the run |
| **Verdict** | All criteria met; autonomy was earned live, exactly as designed |

## Method

The [M8 setup](2026-09-10-hetzner-m8.md) plus one new resource: an
`OperatorPolicy` for the production environment granting
`converge-services` autonomy after **one** verified receipt, capped at four
autonomous executions per hour, with quiet hours 01:00–05:00 declared (and
not in effect during the run). The operator watched remotely over the
gateway's mTLS alerts route. Only public entry points were used.

## Results

Two identical induced failures (`systemctl stop postgresql@17-main`),
handled differently because trust changed between them:

- **Cycle 1 — autonomy withheld, trust earned.** The declared alert fired
  and the operator proposed convergence, but the autonomy pass **refused to
  execute** and recorded why: `insufficient verified history for
  converge-services: 0 of 1 required`. A human approved the proposal; it
  executed, the alert resolved, and the receipt landed as verified with
  `approval.mode: human`. That receipt is the trust
- **Cycle 2 — zero human involvement.** PostgreSQL stopped at 19:45:50; the
  alert fired at 19:47:16; the operator pass at 19:47:23 found the open
  proposal, and the autonomy decision now passed every gate (one verified
  receipt, rate limit clear, quiet hours inactive). It executed at
  19:47:24 under `approval: {"mode": "autonomous", "policy":
  "production-operator"}`, watched the same alert resolve, and receipted
  **verified at 19:47:56**. Failure to verified remediation: 2 minutes
  6 seconds, with no human in the loop
- **The receipt trail carries the full story** the exit criterion demands:
  detection (the trigger evidence and diagnosis in the proposal), decision
  (cycle 1's recorded withhold reason versus cycle 2's granting policy id),
  action (`executedAt`), and verified outcome (`verifiedAt`, the audit-
  matching detail line)
- **Exit state**: final audit 20/20 compliant; the disposable host and key
  were destroyed

## Observations

1. **An interrupted execution left the truthful state.** One operator
   invocation was killed externally (a tooling timeout on the management
   host) mid-convergence: the service had already been restored, but the
   receipt correctly stayed `proposed` because execution never completed
   its contract. The still-open proposal was picked up by the next
   autonomy pass — the crash-consistency behavior one wants from a
   receipts model, found by accident and worth a regression thought:
   a staleness check for proposals whose trigger already resolved would
   avoid re-executing an idempotent convergence
2. Convergence on an already-converged host is fast: the autonomous
   execute-and-verify cycle took 32 seconds end to end

## Caveats

- Autonomy was exercised for `converge-services` on the alert trigger; the
  drift trigger's autonomous path is covered by unit tests but was not
  exercised live in this run
- The rate limit and quiet hours were declared and evaluated (both clear)
  but their withhold paths were proven in tests, not live
- Single-host fleet, as in every proving run so far

## Cost

One cx23 instance for about ninety minutes: a few euro cents.
